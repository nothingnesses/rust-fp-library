Scoped effects and standard handlers: `Catch` (`catch_handler`), `Local` (`local_handler`), `RefLocal` (`ref_local_handler`), `Bracket` (`bracket_handler`), `RefBracket` (`ref_bracket_handler`), `Span` (`span_handler`), Writer `censor` (`writer_pre_handler`, `writer_post_handler`), Writer `listen` (boundary-split accumulating traversal). All are implemented across the six wrapper families, including the Box-backed families via boundary frames.

Row and program operations: `lift` (Member-generic), `send`, `peel`, `bind`/`map`, `pure`, `extract`, `expand` (both rows), `weaken` (first-order head), `handle`/`run`, `handle_rec`/`run_rec` (MonadRec targets), `handle_with`/`handle_with_handler`, `handle_scoped_with`, `interpose`/`interpose_with_replacer`/`interpose_with_rewriter`, `accumulate_with_first_order` (+ preserving variant), `handle_with_either`, `im_do!` do-notation, `from_free`/`into_free`.

This is substantially more than `run.md` advertises; the documentation gap is recorded in [organisation-naming-documentation.md](organisation-naming-documentation.md) section 3.

## 2. Coverage against purescript-run (checkout)

The checkout contains `Run` plus Reader, State, Writer, Except, Choose, and Internal; it does not contain `Run.Streaming` (upstream purescript-run does).

| purescript-run item                                                                        | Status here          | Notes                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------ | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lift`, `send`, `peel`, `extract`, `expand`                                                | Present              | `expand` is a deep rebuild rather than a coercion (architecture 3.5).                                                                                                                                                                                                                                   |
| `resume` (Church eliminator)                                                               | Absent               | `peel` covers practical use; low value.                                                                                                                                                                                                                                                                 |
| `run` / `interpret`                                                                        | Present              | `handle`/`run` aliases.                                                                                                                                                                                                                                                                                 |

## 4. Port candidates, prioritized

1. Tagged effects (labels). A transparent `TaggedBrand<Label, EBrand>` functor wrapper plus smart-constructor and handler-macro support. Unblocks two same-type effects per row (two States, two Readers), which both references treat as table stakes. Small, self-contained, high leverage.
2. Pure accumulator runners (`runAccum` family analog) for the multi-shot wrappers, then port heftia's NonDet-x-Writer and NonDet-x-State zoo cases as tests. This is the semantic-correctness item; it also decides whether `run.md`'s handler-order claims become true or get corrected.
3. `transactState` scoped handler. Cheap parity win.
4. Streaming on Coroutine: port upstream purescript-run's `Run.Streaming` (producer/consumer/transformer, `connect`/`for`-substitution) or heftia's `Machinery` composition. The local Coroutine effect plus the multi-shot wrappers are sufficient substrate.
5. `ChooseH`-style scoped choice, after item 2 (its zoo semantics depend on threaded accumulators).
6. `runCont` (CPS interpreter family), which also clarifies the future callback-async story.
7. `subsume` row operation (merge duplicate effect occurrences), plus a decision on whether `transform`-without-handling deserves a named method.
8. Delimited continuations (CC/Shift) on the Rc/Arc families. Largest item; needs its own design round (answer-type management, interaction with boundary frames, Box-family impossibility statement). The heftia handlers are small once the substrate exposes "capture the rest of the program as a value", which `peel` plus cloneable continuations already approximate.
9. A decision document on the deferred runtime-sensitive set (Unlift, Provider, Parallel, Timer, Subprocess, general `Io` base effect): not ports yet, but written criteria for when each becomes eligible, per the project principle of documenting limitations explicitly.

## 5. Test and benchmark gaps

- Semantics zoo: NonDet x Writer (both orders), NonDet x State, NonDet x Catch beyond the current Choose-or-throw cases, and (once ported) ChooseH cases. The existing `run_heftia_semantics.rs` is the right home.
- Stack safety: no deep `Run` program tests exist (`stack_safety.rs` covers other types). Add 100k-step programs through `handle`, `handle_rec`, `handle_with` chains, `interpose`, and `expand`, on both Box and Rc families.
- Laws: no property tests target the Run wrappers' Functor/Monad laws or `expand` row-naturality (`expand(prog).handle(h)` versus `prog.handle(h')`); QuickCheck infrastructure already exists in the repo.
- Benchmarks: `effect_rows.rs` and `scoped_operations.rs` exist; add dispatch-position cost (first versus last row position), deep-bind throughput versus plain `Free`, `expand` cost as a function of program size, and boundary-frame overhead for scoped-heavy programs. These directly inform R11 (tail-resumptive fast path) and the `expand` documentation.
